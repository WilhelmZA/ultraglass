Ultraglass supports custom plugins. There are two main types of plugins:

-   [**Input Plugins**](#input-plugins): Apply custom validation logic to or transform user input before the query is sent to a device.
-   [**Output Plugins**](#output-plugins): Interact with the output from a device before it's displayed to the user.

A plugin is a Python file with one or more classes that subclass `InputPlugin` or `OutputPlugin`. Put the file in the `plugins` folder of the Ultraglass app directory, for example `/etc/hyperglass/plugins/`. Reference it by file name, with or without the `.py` extension. Ultraglass ignores a name that does not match a file in that folder.

There are two ways to enable a plugin:

-   List it in a directive's [`plugins`](/configuration/directives.mdx) key. The plugin then runs for queries that use that directive.
-   List it in the top-level [`plugins`](/configuration/config.mdx) key of the main configuration file. The plugin then runs for every query.

## Examples

### Input Plugins

#### Convert a CIDR Prefix to Network and Mask

In this example, the following query is sent to Ultraglass:

```json filename="Example Query"
{
    "query_target": "192.0.2.0/24",
    "query_location": "your_location",
    "query_type": "ip_route_directive"
}
```

The below plugin is defined and referenced by a directive:

```python filename="/etc/hyperglass/plugins/transform_plugin.py"
from ipaddress import ip_network
from hyperglass.plugins import InputPlugin


class TransformCIDR(InputPlugin):
    def transform(self, query):
        target = query.query_target
        target_network = ip_network(target)
        if target_network.version == 4:
            return f"{target_network.network_address!s} {target_network.netmask!s}"
        return target
```

```yaml filename="directives.yaml"
ip_route_directive:
    name: IP Route
    plugins:
        - transform_plugin.py
    field:
        description: IP address or prefix
    rules:
        - condition: "0.0.0.0/0"
          action: permit
          command: "show ip route {target}"
        - condition: "::/0"
          action: permit
          command: "show ipv6 route {target}"
```

When the query is received, the query target is transformed after validation, resulting in this being sent to the device:

```text
show ip route 192.0.2.0 255.255.255.0
```

instead of:

```text
show ip route 192.0.2.0/24
```

#### Validate User Input

In this example, we want to perform some custom validation not available via the directives `condition` API. For instance, say you wanted to ensure a query target isn't contained within a dynamic list of [bogon prefixes from Team Cymru](https://www.team-cymru.com/bogon-networks).

Ultraglass runs input plugin validation after the directive's rules pass. Return `False` to reject the query with the error `No matched validation rules`. Return `True` to accept it without running the remaining plugins. Return `None` to pass the decision to the next plugin.

```python filename="/etc/hyperglass/plugins/validation_plugin.py"
from ipaddress import ip_network

from hyperglass.plugins import InputPlugin
from hyperglass.external import HTTPClient

class BogonPlugin(InputPlugin):
    def validate(self, query):
        target = ip_network(query.query_target)

        with HTTPClient(base_url="https://team-cymru.org") as client:
            response = client.get("/Services/Bogons/fullbogons-ipv4.txt")

        bogon_strings = [
            line.strip() for line in response.text.split("\n") if line.strip() and not line.startswith("#")
        ]
        bogons = [ip_network(bogon) for bogon in bogon_strings]

        for bogon in bogons:
            if target.version == bogon.version and target.subnet_of(bogon):
                return False # Return false to fail validation.
        return None
```

This isn't the best real-world example, since the above plugin would be run on every request, likely resulting in slow query responses, but it illustrates the power of plugins.

### Output Plugins

#### Redact Sensitive Information

Say one of your directives might show some sensitive information in the query output. Using an output plugin, we can replace any text matching a pattern (or multiple patterns) with some other text.

An output plugin enabled by a directive runs only on devices whose platform is in the plugin's `platforms` list. Ultraglass calls `process()` with keyword arguments `output` and `query`. `output` is a tuple of strings, one per command, or a parsed table when the device has `structured_output` set. Each plugin receives the previous plugin's result.

```python filename="/etc/hyperglass/plugins/redact.py"
import re
import typing as t
from hyperglass.plugins import OutputPlugin

SENSITIVE_PATTERN = re.compile("SuperSecretInfo")

class Redact(OutputPlugin):
    platforms: t.Sequence[str] = ("cisco_ios", "juniper")

    def process(self, *, output, query):
        result = []
        for each_output in output:
            redacted = SENSITIVE_PATTERN.sub("<REDACTED>", each_output)
            result.append(redacted)
        return result
```
