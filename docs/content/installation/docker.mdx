### Download Ultraglass

```shell copy
mkdir /etc/hyperglass
touch /etc/hyperglass/hyperglass.env
git clone https://github.com/WilhelmZA/ultraglass.git --depth=1 /opt/hyperglass
cd /opt/hyperglass
```

Clone into `/opt/hyperglass`. The sample `systemd` service runs `docker compose` from that directory. The service also reads `/etc/hyperglass/hyperglass.env`, and `systemd` does not start it if that file is missing.

<Callout type="info">The sample `compose.yaml` builds the image from source. Release images are also published as `wilhelmza/ultraglass` on Docker Hub and `ghcr.io/wilhelmza/ultraglass`, for `linux/amd64`. Each image tag is a release version without the `v`, for example `3.6.2`. Release candidates have their own tags, for example `3.6.0-rc.2`. The `latest` tag is the newest stable release and does not point to a release candidate.</Callout>

### Optional: Quickstart

Do this if you want to verify the Ultraglass page with a fake device before connecting real network devices.

```shell copy
cp /opt/hyperglass/.samples/sample_devices.yaml /etc/hyperglass/devices.yaml
cd /opt/hyperglass
docker compose up
```

Open http://localhost:8001. The first start builds the UI, which takes a few minutes.

### Create a `systemd` service

For host nginx, bind the published application port to loopback before exposing the site:

```shell
HYPERGLASS_BIND_ADDRESS=127.0.0.1 docker compose up -d hyperglass
docker compose port hyperglass 8001
```

The published address must be `127.0.0.1:8001`. Keep `HYPERGLASS_HOST=0.0.0.0` inside the container. The nginx sample overwrites forwarding headers with the connecting client address.

Find the Docker gateway that connects host nginx to the application:

```shell
docker inspect "$(docker compose ps -q hyperglass)" --format '{{range .NetworkSettings.Networks}}{{println .Gateway}}{{end}}'
```

Configure only that gateway as a trusted proxy. Replace the example address below with the actual gateway:

```yaml
web:
    client_ip:
        header: X-Real-IP
        trusted_proxies:
            - 172.18.0.1/32
```

Restart Ultraglass after changing the configuration. A forged forwarding header must not change the visitor address through nginx. Do not trust the whole bridge subnet or expose the application port directly when trusting its gateway.

<Callout type="info">Before you create and start the Ultraglass service, verify whether you need to change any [environment variables](environment-variables.mdx).</Callout>

```shell copy
cp /opt/hyperglass/.samples/hyperglass-docker.service /etc/hyperglass/hyperglass.service
ln -s /etc/hyperglass/hyperglass.service /etc/systemd/system/hyperglass.service
systemctl daemon-reload
systemctl enable hyperglass
systemctl start hyperglass
```
