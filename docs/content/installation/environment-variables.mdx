---
title: Environment Variables
description: Ultraglass environment variables
---

Some environment variables must be supplied before Ultraglass can start or read its configuration files. Most deployments can use the defaults.

Set environment variables in the shell that starts Ultraglass, or in `/etc/hyperglass/hyperglass.env`. Ultraglass does not read that file itself. The sample `systemd` services load it with `EnvironmentFile`.

With Docker, `compose.yaml` mounts the host directory in `HYPERGLASS_APP_PATH` at `/etc/hyperglass` in the container. Inside the container, the application path is always `/etc/hyperglass`.

## Docker

With Docker, `hyperglass.env` sets values for `docker compose`, not for the container. The container receives only the variables that `compose.yaml` passes: `HYPERGLASS_HOST`, `HYPERGLASS_PORT`, `HYPERGLASS_DEBUG`, `HYPERGLASS_DEV_MODE`, `HYPERGLASS_REDIS_HOST`, `HYPERGLASS_DISABLE_UI` and `HYPERGLASS_APP_PATH`. The other variables in the table have no effect when you set them in `hyperglass.env`.

To pass another variable, create `compose.override.yaml` next to `compose.yaml` in `/opt/hyperglass`. `docker compose` merges that file automatically. A file path, such as `HYPERGLASS_CA_CERT`, must be a path inside the container, for example under `/etc/hyperglass`.

```yaml filename="/opt/hyperglass/compose.override.yaml"
services:
    hyperglass:
        environment:
            - HYPERGLASS_WORKERS=4
            - HYPERGLASS_REDIS_DB=2
            - HYPERGLASS_CA_CERT=/etc/hyperglass/ca.pem
```

## Variables

| Variable Name               | Type    | Default           | Description                                                                                                        |
| :-------------------------- | :------ | :---------------- | :----------------------------------------------------------------------------------------------------------------- |
| `HYPERGLASS_DEBUG`          | boolean | `false`           | Enable debug logging                                                                                               |
| `HYPERGLASS_DEV_MODE`       | boolean | `false`           | Enable developer mode. Use this only while developing or troubleshooting Ultraglass.     |
| `HYPERGLASS_DISABLE_UI`     | boolean | `false`           | If set to `true`, the Ultraglass UI is not built or served. Access is then through the REST API.     |
| `HYPERGLASS_APP_PATH`       | string  | `/etc/hyperglass` | Directory where Ultraglass configuration files and static web UI files are stored.                              |
| `HYPERGLASS_REDIS_HOST`     | string  | `localhost`       | Host on which Redis is running.                                                                                    |
| `HYPERGLASS_REDIS_PASSWORD` | string  | —                 | Redis password, if any.                                                                                            |
| `HYPERGLASS_REDIS_DB`       | number  | `1`               | Redis database number.                                                                                             |
| `HYPERGLASS_REDIS_DSN`      | string  | —                 | Redis DSN. If supplied, overrides `HYPERGLASS_REDIS_HOST`, `HYPERGLASS_REDIS_DB`, and `HYPERGLASS_REDIS_PASSWORD`. |
| `HYPERGLASS_HOST`           | string  | `::1`             | Address on which Ultraglass listens for requests. The default is `::` when `HYPERGLASS_DEBUG` is `true`. The Docker image sets `0.0.0.0`. |
| `HYPERGLASS_PORT`           | number  | `8001`            | TCP port on which Ultraglass listens for requests.                                                                 |
| `HYPERGLASS_WORKERS`        | number  | —                 | Number of web server workers. If not supplied, Ultraglass uses 1 worker in debug mode, else 2 workers per CPU core. |
| `HYPERGLASS_CA_CERT`        | string  | —                 | Path to a CA certificate file. Ultraglass uses it to validate HTTPS certificates on outbound requests. If not supplied, system CAs are used.               |
