## Message Customization

Ultraglass keeps user-facing messages configurable so each deployment can describe its own service. The following messages may be adjusted as needed:

| Parameter                       | Type   | Default Value                                            | Description |
| :------------------------------ | :----- | :------------------------------------------------------- | :---------- |
| `messages.authentication_error` | String | Authentication error occurred.                           | Displayed when Ultraglass is unable to authenticate to a device. Usually, this indicates a configuration error. |
| `messages.connection_error`     | String | Error connecting to \{device_name\}: \{error\}           | Displayed when Ultraglass is unable to connect to a device. Usually, this indicates a configuration error. Use `{device_name}` or `{device}` to show the device name, and `{error}` to show the connection error. Both device placeholders work. |
| `messages.device_command_error` | String | The query command failed on \{device_name\}.             | Displayed when a device rejects a command or denies permission to run it. `{device_name}` identifies the device. |
| `messages.general`              | String | Something went wrong.                                    | Displayed when an error occurs that Ultraglass did not anticipate or handle correctly. If this appears in production, enable [debug logging](/installation/environment-variables.mdx) with `HYPERGLASS_DEBUG` and review the logs before opening a bug report. |
| `messages.invalid_input`        | String | \{target\} is not valid.                                 | Displayed when a query target's value is invalid in relation to the corresponding query type. `{target}` will be used to display the invalid target. |
| `messages.no_input`             | String | \{field\} must be specified.                             | Displayed when a required field is not specified. `{field}` will be used to display the name of the field that was omitted. |
| `messages.no_output`            | String | The query completed, but no matching results were found. | Displayed when Ultraglass can connect to a device and execute a query, but the response is empty. |
| `messages.not_found`            | String | \{type\} '\{name\}' not found.                           | Displayed when an object property does not exist in the configuration. `{type}` corresponds to a user-friendly name of the object type (for example, 'Device'), `{name}` corresponds to the object name that was not found. |
| `messages.request_timeout`      | String | Request timed out.                                       | Displayed when the [`request_timeout`](/configuration/config.mdx#top-level-parameters) time expires. |
| `messages.target_not_allowed`   | String | \{target\} is not allowed.                               | Displayed when a query target is implicitly denied by a configured rule. `{target}` will be used to display the denied query target. |
| `messages.feature_not_enabled`  | String | \{feature\} is not enabled.                              | Accepted, but not displayed by the current code. |
| `messages.invalid_field`        | String | \{input\} is an invalid \{field\}.                       | Accepted, but not displayed by the current code. |
| `messages.invalid_query`        | String | \{target\} is not a valid \{query_type\} target.         | Accepted, but not displayed by the current code. |
| `messages.no_response`          | String | No response.                                             | Accepted, but not displayed by the current code. |

##### Example

```yaml filename="config.yaml"
messages:
    general: Something went wrong.
```
